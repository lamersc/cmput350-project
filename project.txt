Implementation overview
=======================

This project is a galaga implementation built on top of the game and engine from part 1a. On the engine side I implemented the
cubic Bezier curves (*had fun implementing the wrong one initially from notes lol*), collision between lines, circles and
rectangles, with a single collision point for directed lines, and draw contexts that applys each object's offset and rotation
so every object just draws in its own local space (*helped "click" a lot of the work game engines such as godot do*). The
EngineView lets objects iterate over everything inside the engine, and keys and general events are registered as notifications
instead of being broadcast to all objects, e.g. the player listens for "MoveLeft" and "Fire" rather than the basic string
codes like before. I tried to keep the engine API as close to the spec as possible, though added my own math functions when
helpful in keeping code tidy.

The Galaga class runs the game as a finite state machine. It starts waiting for coins (using the "MAME" convention), then
shows the level number, score and player ship during startup. From there, five waves of eight enemies fly in along Bezier
curves to try and match galaga arcade machines I've played. Once all the enemies have all settled into formation, the game
enters the gameplay loop, where enemies hover and take turns attacking in rounds, done using the engine's iterator to decide
attack order. Clearing a wave loops back to startup with the next level. On player death, the game waits for formation to
settle and then respawns the player with their remaining lives. If the player runs out of lives, a "game over" message is
shown for a few seconds before they're sent back to the coin screen.

Enemies come in three visually distinct types with different health, point values and attack beziers; Enemy1 has 2=two health
and changes color as it takes damage, the others have one (wanted to do more with this, but scope creep was getting me.
Bullets get destroyed on contact, draw a small explosion at the collision point when destroyed, and die along with their
parent (was too difficult without this). The player is kept in the screen and can only have two bullets shot at a
time by iterating how many player bullets are currently alive in the world (wow, thinking now, this could've just been a counter...)
